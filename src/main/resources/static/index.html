      Bloom pre-screen

      Each store keeps a tiny bit-array sketch of what it stocks. A 0 bit proves the item is absent, so the store is skipped. A full match only means "possibly", so it is confirmed against the real inventory.

      Greedy weighted set cover

      Each round picks the store with the lowest cost per newly covered item. Cost = stop cost + travel to and from home, plus λ × price premium. With λ = 0 the result is guaranteed within H(n) of optimal. We also solve it exactly by DP over all 2ⁿ item subsets to check.

        3

        Metric TSP: double-tree + 2-opt

        Kruskal builds a minimum spanning tree, with edges sorted by our randomized quicksort and cycles blocked by union-find. A preorder walk with shortcuts gives a tour at most 2× optimal. 2-opt then uncrosses edges. For small trips we also run exact Held-Karp to measure the gap.

        4

        Price check with randomized quickselect

        For every item, the median price across all Powai stores is found in expected O(n) with a random pivot. A full sort is never needed. The marker shows where your price sits.

        How Sweep thinks

        You have a list and limited time. Most people go to the nearest shop, then the next nearest, until they've got everything. Others chase the lowest price per item and zig-zag across the suburb. Sweep treats the trip as two textbook problems and solves both.

          Why approximate?

          Set cover and TSP are both NP-hard. Exact solvers blow up exponentially: Held-Karp on 25 stops would need about 2·1010 table cells. Sweep therefore runs polynomial algorithms with proven bounds. On small trips it also runs the exact solvers, so you can see the true gap instead of trusting the bound. It never claims a route is optimal unless Held-Karp has confirmed it.

          Assumptions and limits

          • Distances are straight-line × 1.3 road factor. Scaling keeps the triangle inequality the 2-approximation needs. Real road graphs can break it.
          • The dataset is synthetic but realistic: 36 Powai shops, 176 items, 770 listings with prices and stock levels. A seeded Python script generates it reproducibly.
          • Each item is bought at a single store. If no open store has enough units, Sweep reports it instead of splitting the purchase or guessing.
          • With λ > 0 the price-premium term is a heuristic and has no H(n) guarantee. The UI says so.
